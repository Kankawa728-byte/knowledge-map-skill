# 内容怎么写

这张图要做到：读者完全没学过这个领域，只看这张图，也能弄懂每个知识点，并且看出知识点之间怎么连起来。原文只当出处，不当前提。

## 1. 读材料

- 全部读完再动笔：正文、图、表、公式、附录、讲者备注。课件里的图和公式页要渲染成图片看，提取出来的文字会漏掉它们。
- 看不了 PDF 页面时（例如 Claude Code 的 Read 缺 pdftoppm，或者 Codex 不能直接看 PDF），用 PyMuPDF（`fitz`）抽文字、把页面存成 PNG，再用看图片的工具看：Claude Code 用 Read，Codex 用 view_image。
- 抽出来的文字存成文件留着。生成时用 `build.py --text` 把它或原文 PDF 传进去，核对每条 quote 是不是原文原句。
- 论文按这个顺序读：摘要、引言里的问题和贡献、方法、实验、局限、相关工作；附录按需。
- 边读边记三样东西：反复出现的术语；"因为、所以、但是、相比、为了"这类句子，它们就是关系；每个说法在原文的位置。

## 2. 选知识点

一张图放 25 到 45 个知识点。少于 20 个说明拆得太粗，多于 45 个就拆成几张图，再做一张总图，总图的每个分区对应一张分图。

可以当节点的：概念、方法、组件、步骤、问题或现象、指标、贯穿全文的例子；论文里还有关键论点和关键结果。

不当节点的：章节标题、作者、一笔带过的名词、只出现一次且和别的知识点没关系的细节。同一个东西有几个名字时只留一个节点，别名写进 detail。

原文默认读者已经会、但不会就看不懂的东西，做成背景节点（`background = true`），放进"先懂这些"分区。读论文时这一区常常少不了。

## 3. 分区

3 到 7 个分区，每区 3 到 9 个节点。

- **课件、讲义、录播**：按主题或章节分。一个分区回答一个问题，例如"找段落：按字面还是按意思"。
- **论文**：默认按论文的论证顺序分，按实际内容合并或删掉：先懂这些、研究问题、已有方法和它们的不足、本文方法、关键组件、实验和证据、局限和以后的方向。
- **综述、观点文章（review、perspective）**：没有单一的“本文方法”。按这几块分：要解决什么问题、有哪几条技术路线、已有哪些研究证据、还有什么没解决、作者设想的方向。“已有证据”“仍未解决”“作者设想”分开放，读者才分得清哪些已经做到、哪些只是提议。

分区标题写成能看懂的短语，前面加圆圈编号，例如"③ 本文方法"。

## 4. 关系

关系是这张图的核心。每条关系回答一个问题：这两个知识点为什么连在一起？

### 五种关系

| kind | 颜色 | 什么时候用 | 标签例子 |
|---|---|---|---|
| good | 绿 | 一个解决、改进、擅长另一个；问题指向它的解法 | 擅长、太慢 → 改用、缓解 |
| bad | 红虚线 | 失败、局限、导致问题 | 败：词汇不匹配、只加 top-k，所以 |
| part | 灰 | 组成、步骤、用到、怎么训练、下一步 | 损失函数、第一步、分簇用 |
| link | 橙 | 互补、对比、同类、相似思路 | 互补、同一思路、对比 |
| evid | 紫 | 证据支持论点、指标衡量对象、实验验证 | 证明、衡量、消融实验显示 |

### 写法

- **方向**：问题指向解法，方法指向它擅长或败在的情形，整体指向部分，证据指向论点，指标指向它衡量的东西。
- **label**：动词短语，尽量不超过 8 个汉字。读法是"from 〔label〕 to"。
- **text**：一整句话，把为什么连在一起说清楚，句末括号写出处，例如"（p34）""（§3.2，Table 2）"。读者只看这一句也能懂。
- **跨分区的关系最值钱**，它们说明各部分怎么连起来。每个分区至少要和另一个分区有一条关系。
- 关系数大约是节点数的 1 到 1.5 倍。一个节点连出 7 条以上时，考虑拆开这个节点或删掉弱的关系。
- 不画只说明归属的线，例如"属于""是一种"。归属靠分区表达。
- **原文明说的关系**写 `src`。**原文没直接说、是推断出来的关系**写 `inferred = true`，并在 text 里写出推断的依据。推断的关系要少，只在它能帮读者把两块内容连起来时才画。

## 5. 节点解释

点开节点看到的内容按这个顺序显示：一句话、详细解释、展开（例子和公式）、原文依据、补充、相连的关系。

### title 和 sub

- `title`：原文用的术语。原文是英文就保留英文，例如"Dense · bi-encoder"。
- `sub`：框里的一行小字，不超过 14 个汉字，提示它是干什么的。

### one：一句话

用大白话下定义，不超过 60 个字，不用还没解释过的术语。例如："把几份排名合成一份，只看名次，不看分数。"

### detail：详细解释

读者是零基础，而且注意力容易散。写法：

- 120 到 400 个字。更长的内容放进 `more`。
- 分成 2 到 4 小块，每块用粗体小标题开头。常用的小标题是：**是什么：**、**怎么做：**（或 **怎么运作：**）、**为什么需要它：**、**别混淆：**。按需要选，不必四个都写。
- 每块不超过三句。一句只说一件事。
- 术语第一次出现时在同一句里解释。英文术语保留原文，后面跟中文意思。
- 能用原文自己的例子就用原文的例子。
- 只写原文支持的内容。原文没有的东西放进 `sup`。
- 只讲知识。核验过程和“不能写成……”这类写给自己的提醒，不写进给读者看的正文。读者需要知道的限制，用一句平常话写明，例如“这是计算值，还没有实测”，或者用 `evidence` 标出来。全图通用的说明写进顶层 `notes`。
- 照原文的分寸用词。不用“暴涨”“秒级”“全面超越”这类夸张词；原文说“约”“可达”“预测”，就照着写。
- 把原文的普通词译成专业术语之前，先确认意思没变。例如 primary drugs 是“主要药物”，不等于临床上的“一线药物”。

### more：例子、公式和细节

放算例、推导、代码、长公式、和别的方法的细节对比。公式后面紧跟一句话，逐个说明符号是什么意思。

### src：原文依据

- 位置要具体：课件写页码"p19"；论文写章节、公式、图、表，例如"§3.2，Eq. 4""Fig. 2"；录播写时间"12:30"。
- `quote` 摘一个原文的关键短语，用原文的语言，不超过 15 个词。不要大段照抄。
- quote 照抄原文，不改写、不翻译。生成时加了 `--text`，`build.py` 会逐条核对，找不到的报警告。
- 大部分知识点都要有 quote。过半的非背景节点没有 quote 时，`build.py` 会警告。

### sup：补充

原文没写、但读懂需要的东西：背景知识、你加的类比、你自己算的数、别的资料里的说法。这一块在页面上会标"原文没有写"。

整个知识点都是原文没讲的背景时，不用 sup，直接给节点写 `background = true`。

### evidence：证据等级

论文里的关键结果、计算出来的数和作者的设想，读者容易混成一类。用 `evidence` 标出来，页面上显示成小标签：

| 值 | 什么时候用 | 例子 |
|---|---|---|
| 实测 | 实验测出来的结果，本文做的、或综述转述别人做的都算 | 某模型在测试集上准确率 98% |
| 模拟 | 计算、仿真或理论估计的值，还没有实验测到 | 仿真预测增强因子超过 10⁷ |
| 设想 | 作者提出的方向或设计，还没有做出来 | 作者设想建一个光谱和组学配对的数据库 |

- 概念、方法、组件这类节点不标。
- 一个节点里混着几种证据时，按它的主要结论标，其余的在 detail 里用一句话说明。
- 关系也可以标，常用在“证明”“显示”这类 evid 关系上。
- 论文图（`mode = "paper"`）一处 evidence 都没有时，`build.py` 会警告。

## 6. 关系链

关系链让读者按"因为……所以……"一步步看，一次只亮一条线。

- 4 到 8 条，每条 3 到 7 步。
- 相邻两步最好共用一个节点，读起来不跳。
- 标题写成一个问题或一个结论，例如"为什么要两种检索器""一千万段怎么毫秒级搜到"。
- 合起来要覆盖材料的主线。论文至少要有一条"论文的故事"：研究问题，到已有方法的不足，到本文方法，到证据，再到局限。这条放在第一条；它经过的分区不到一半时，`build.py` 会警告。

## 7. 交付前自查

- [ ] 挑三个最难的节点，只读面板内容，确认零基础的人能讲出它是什么、为什么需要它。
- [ ] 每个数字、公式、结论都对回原文核对过；自己算的数写进 sup，并写明是算的。
- [ ] 原文没有的内容都在 sup 或背景节点里；推断的关系都标了 inferred。
- [ ] detail 里没有写给自己的提醒，没有夸张词；译成术语的词对过原意。
- [ ] 论文图的关键结果、模拟值和作者设想都标了 evidence。
- [ ] quote 都照抄原文，生成时用 `--text` 核对过。
- [ ] 全图通用的说明写在 notes 里，来源名称是短名。
- [ ] 同一个东西全图只用一个名字。
- [ ] 每个分区都和别的分区连上了；没有孤零零的节点。
- [ ] 关系链合起来讲得出材料的主线。
- [ ] 没有加考试功能：易错标记、考试标签、练习题。用户当次明确要求时才加。
- [ ] 成品里没有 Claude、Codex 或其他 AI 的署名。
