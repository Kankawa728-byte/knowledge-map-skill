# 排位置和修版面

位置是手排的：先想清楚哪些分区挨着、每个节点放在哪一格，`build.py` 按网格算出坐标，`check.py` 在浏览器里查问题。全自动排版在知识点多、跨区连线多的时候会乱，所以不用。

## 网格

- 分区之间是一张网格：`grid = [列, 行]`。
- 分区内部也是网格：`size = [列数, 行数]`，节点用 `pos = [列, 行]` 放进去，从 0 数，可以写 0.5 这样的半格。
- 区内一列宽 230，一行高 110。左右相邻的两个节点，框宽最好都不超过 210。框宽由标题和副标题的字数决定，`build.py` 超了会警告。
- 同一网格列的分区一样宽，同一网格行的分区一样高。区内的节点网格在分区里水平居中。

## 先排分区

1. 把分区之间的关系数一下，连线多的两个分区要挨着，左右挨或上下挨都行。
2. 主线从左到右、从上到下走。例如：上排"为什么、怎么找、怎么找得快"，下排"怎么评、怎么排准、怎么上线"。
3. 分区一般排两行，每行 2 到 4 个。

## 再排节点

常用的几种摆法：

- **竖着一条链**：A `[0,0]`、B `[0,1]`、C `[0,2]`。
- **一分几**：父节点在上面中间，例如 `[1,0]`；子节点排在下一行 `[0,2]`、`[1,2]`、`[2,2]`。
- **交叉的 X**：两个方法放在第 1 行左右两边，它们各自擅长的例子放在第 0 行，擅长的放正上方，失败的放斜对面。两条"败"线交叉成 X，一眼看出"各败在对方擅长的地方"。这时把两条线的 `lp` 调到 0.72，让标签靠近各自的目标，避免两个标签在交叉点重叠。
- **两个合成一个**：两个节点放在同一行，合成的节点放在它们下一行的中间（半格）。
- **跨区枢纽**：有跨区连线的节点放在靠近对方分区的那一侧。

别把一个节点放在另外两个相连节点的连线上。

## 按 check.py 的报告修

| 报告 | 先试 | 再试 |
|---|---|---|
| 节点重叠 | 把其中一个挪到空格子 | 缩短标题或副标题 |
| 连线穿过别的节点 | 给这条线加 `bend`，从 ±20 试到 ±120 | 挪开挡路的节点 |
| 连线文字压到节点 | 调 `lp`，在 0.2 到 0.8 之间 | 缩短 label |
| 连线文字互相重叠 | 两条线的 `lp` 往相反方向调 | 缩短 label |
| 连线穿过别的连线文字 | 调被穿的那条线的 `lp` | 给穿过去的线加 `bend` |
| 压到分区标题 | 给分区写 `title_align = "end"` | 挪开节点或给线加 `bend` |
| 节点里的字超出框 | 缩短标题或副标题 | |
| 节点超出分区 | 改大分区的 `size`，或改 `pos` | |
| 同一对节点有两条线（`build.py` 警告） | 给其中一条加 `bend` | 合并成一条 |
| 手机宽度下整页能左右滑动 | 一般是页头的字太长，缩短 `title` 或 `intro` | |
| 公式和紧挨着的标点被拆到两行 | 用新版 `build.py` 重新生成：它会把公式和两边紧挨着的标点包在一起 | 那个标点不在 `build.py` 的 `_OPEN_P`、`_CLOSE_P` 里时，把它加进去 |

`bend` 为正时，线往"从 from 走向 to"的右手边弯；为负时往左手边弯。弯曲最多的地方偏离直线大约是 `bend` 的四分之三。

一张图要加 6 处以上 `bend` 才干净，说明分区或节点排得不好，回头重排比一处处修快。加 bend 的关系超过 6 条、或者单条 bend 超过 ±120 时，`build.py` 会警告。

## 看截图

`check.py --png <目录>` 存这些图：

- `map_r*c*.png`：整张图按 1:1 切成的小块。全部看完，看线是不是太乱、跨区长线多不多、有没有看着别扭的地方。
- `drawer_full.png`：内容最长的那个节点的完整面板。看分段、公式、出处是否正常。
- `desktop_node.png`、`desktop_chain.png`：桌面宽度下点开节点和走关系链的样子。
- `mobile_map.png`、`mobile_node.png`、`mobile_text.png`：手机宽度下的图、底部面板和文字版。

浏览器里打开 HTML，地址后面加 `#check`，左下角会显示同一份检查报告。地址后面加 `#n=节点id`，打开时直接点开那个节点。
