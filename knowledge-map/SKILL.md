# 知识关系图

把一份或几份学习材料，做成一个能离线打开的 HTML：知识点是节点，连线上写着两个知识点是什么关系，例如"败在""改用""组成""证明"。点一个知识点，只亮出和它相连的线，旁边弹出面板讲清楚这个知识点。点一条线，看这条关系的完整解释。还可以按"关系链"一步一步看，一次只亮一条线。

读者默认完全没学过这个领域，而且注意力容易散。所以每个节点的解释要能单独读懂，页面一次只突出一件事。

## 什么时候用

- 用户要关系图、概念图、知识图谱、思维导图，或者要"把知识点之间的关系画出来"。用户说"思维导图"时也做这种关系图，不做按章节展开的树。
- 材料可以是课件、讲义、录播字幕、论文，也可以几种一起用。
- 做讲义 PDF、速查卡、过关题、儿童版都不用它。
- **不带考试功能**：不加易错标记、考试标签、练习题或自测。这是用户 2026-10-23 定的。用户当次明确要求时才加。

## 输入和输出

| | 内容 |
|---|---|
| 输入 | 用户给的材料。读不了的格式先转成文字或图片再读。 |
| 数据文件 | `<名字>.kmap.toml`，写法见 [references/format.md](references/format.md) |
| 成品 | `<名字>.html`，和数据文件放在一起。单个文件，不联网也能打开，公式正常显示。 |
| 位置 | 用户指定的位置。没指定时按下面"放在哪"选。 |

### 放在哪

用户指定了位置就放那里。没指定时，按材料和当前项目的关系选：

- **材料属于当前项目**：放在项目存学习材料的文件夹。
- **材料和当前项目无关**：用户说了"只是试用""不是我们领域""不要进知识库"，或者材料明显不属于这个项目。这时在材料原件旁边新建一个文件夹，数据文件和 HTML 都放进去；材料的内容也不写进项目的知识库或记忆。
- **拿不准属不属于项目，或者当前目录不是项目、又不知道原件在哪**：问一句。

## 步骤

Claude Code 和 Codex 都用这份说明。下面命令里的 `<skill 目录>` 是本 SKILL.md 所在的文件夹。

1. 把材料全部读完，图、表、公式页要看图片。读法见 [references/writing.md](references/writing.md) 第 1 节。
2. 选 25 到 45 个知识点，分 3 到 7 个区，列出关系和 4 到 8 条关系链。做法见 writing.md 第 2 到 4、6 节。
3. 在网格上排分区和节点，见 [references/layout.md](references/layout.md)。
4. 用编辑文件的工具写数据文件（Claude Code 用 Write，Codex 用 apply_patch），节点解释按 writing.md 第 5 节写。不要用 echo、printf 这类 shell 命令写，反斜杠会被吃掉。完整的写法范例是 `examples/demo.kmap.toml`。
5. 生成，改到没有错误，警告逐条判断：

   ```bash
   python "<skill 目录>/scripts/build.py" "<数据文件>" --text "<原文>"
   ```

   `--text` 给原文的 PDF，或第 1 步抽出来的文字文件，可以给多个。给了它，`build.py` 会核对每条 quote 能不能在原文里找到。

6. 查版面并截图，按 layout.md 修到报"没有问题"：

   ```bash
   python "<skill 目录>/scripts/check.py" "<成品.html>" --png "<临时目录>"
   ```

   临时目录建在当前工作目录下最稳妥，例如 `.kmap_shots`。Codex 的沙箱可能不让写工作目录以外的地方。

7. 看截图：`map_r*c*.png` 一张不落地看完，再看 `drawer_full.png`、`desktop_chain.png` 和三张 `mobile_*.png`。看到问题就回到第 4 步。
8. 按 writing.md 末尾的清单自查，删掉临时截图，再交付。

`build.py` 换算公式要用 latex2mathml；`check.py` 要用 playwright、Pillow 和本机的 Chrome。缺哪个 PyPI 库就直接装，并告诉用户装了什么。运行这两个脚本不要加 `python -I`，加了会找不到装在用户目录里的库。在 Codex 里，装库要联网，`check.py` 要开浏览器，沙箱可能拦下来：按提示申请批准；用户不批准时，交付时写明版面没有检查。

## 定型的规矩

1. **节点解释能单独读懂。** 零基础的人不看原文也能懂。detail 写 120 到 400 个字，分小块，用粗体小标题开头；更长的内容放进 more。
2. **原文和补充分开。** 原文有的内容写进 detail，并在 src 里给出处。原文没有的内容写进 sup；整个知识点都是背景时，给节点标 `background = true`。全图通用的说明写进顶层 `notes`，不塞进来源名称。
3. **关系要有依据。** 原文明说的关系写 src；推断出来的关系标 `inferred = true`，并在 text 里写依据。
4. **分清证据等级。** 论文的关键结果、计算出来的值和作者的设想，用 `evidence` 标成实测、模拟或设想，不靠正文里的提醒话。
5. **公式用 LaTeX 写**，生成时转成浏览器自带的 MathML。
6. **一张图 25 到 45 个知识点。** 材料更多时拆成几张，再加一张总图。
7. **样子不随手改。** 页面样式和交互都在 `assets/template.html`。要加功能就改模板，改完把 `examples/demo.kmap.toml` 生成到临时目录，跑 `check.py --png`，确认示例图没坏、截图正常。改了 `build.py` 的文字处理时，再把 `examples/wrap_case.kmap.toml` 生成一次跑 `check.py`，应当报"没有问题"。改了 quote 核对时，用 `examples/quote_case.kmap.toml` 加 `--text examples/quote_case.txt` 生成一次，应当正好报 3 条"找不到"。
8. **成品里不写 Claude、Codex 或其他 AI 的署名。**

## 完成条件

- `build.py` 没有错误，`check.py` 报"没有问题"。
- 截图全部看过，writing.md 末尾的清单逐条做过。
- 回复里给出成品路径，写明哪些内容没有核实。能直接给用户发文件的环境（例如 Claude Code 桌面版的 SendUserFile）就把 HTML 发过去。
